# T1606.001: Web Cookies

- Catalog: [T1606.001](https://attack.mitre.org/techniques/T1606/001)
- Kind: sub-technique · ATT&CK 19.2
- Domains: enterprise-attack
- Version: 1.1

## Technique

Adversaries may forge web cookies that can be used to gain access to web applications or Internet services. Web applications and services (hosted in cloud SaaS environments or on-premise servers) often use session cookies to authenticate and authorize user access.

Adversaries may generate these cookies in order to gain access to web resources. This differs from [Steal Web Session Cookie](https://attack.mitre.org/techniques/T1539) and other similar behaviors in that the cookies are new and forged by the adversary, rather than stolen or intercepted from legitimate users. Most common web applications have standardized and documented cookie values that can be generated using provided tools or interfaces.(Citation: Pass The Cookie) The generation of web cookies often requires secret values, such as passwords, [Private Keys](https://attack.mitre.org/techniques/T1552/004), or other cryptographic seed values.

Once forged, adversaries may use these web cookies to access resources ([Web Session Cookie](https://attack.mitre.org/techniques/T1550/004)), which may bypass multi-factor and other authentication protection mechanisms.(Citation: Volexity SolarWinds)(Citation: Pass The Cookie)(Citation: Unit 42 Mac Crypto Cookies January 2019)

## Procedure

1. **Applicability gate.** If none of the platforms/domains exist in scope, record `T1606.001 N/A: <reason>` and stop.
2. **Instance inventory.** Hosts, identities, SaaS apps, ICS nodes, mobile devices. One workstation is not an inventory.
3. **Oracle.** Define pass/fail: procedure succeeded (control bypassed / action completed) vs blocked vs detected.
4. **Execute / emulate.** Follow the technique description as the minimum procedure set. Persist command output, proxy logs, or pcap under `/tmp` or the engagement dir and **re-read** it.
5. **Sub-techniques.** If this ID has children, open each child file and run it. Parent-only testing is incomplete when sub-techniques exist.
6. **Detection check.** Using the same evidence, ask whether the listed data sources would have fired. Missing telemetry is a finding (visibility gap), not a skip.
7. **Mitigation negation.** For each mitigation below, retry with the control on and bypassed. Unchanged oracle = control failed.
8. **CAPEC / CWE close-out.** Run each mapped CAPEC file in the `capec` skill, then related CWE files in `cwe`. ATT&CK without CWE is a procedure note, not a weakness finding.
9. **Report.** Cite `T1606.001`, tactic, CAPEC/CWE IDs, instance, oracle, evidence path.
