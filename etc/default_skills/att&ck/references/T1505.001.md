# T1505.001: SQL Stored Procedures

- Catalog: [T1505.001](https://attack.mitre.org/techniques/T1505/001)
- Kind: sub-technique · ATT&CK 19.2
- Domains: enterprise-attack
- Version: 1.1

## Technique

Adversaries may abuse SQL stored procedures to establish persistent access to systems. SQL Stored Procedures are code that can be saved and reused so that database users do not waste time rewriting frequently used SQL queries. Stored procedures can be invoked via SQL statements to the database using the procedure name or via defined events (e.g. when a SQL server application is started/restarted).

Adversaries may craft malicious stored procedures that can provide a persistence mechanism in SQL database servers.(Citation: NetSPI Startup Stored Procedures)(Citation: Kaspersky MSSQL Aug 2019) To execute operating system commands through SQL syntax the adversary may have to enable additional functionality, such as xp_cmdshell for MSSQL Server.(Citation: NetSPI Startup Stored Procedures)(Citation: Kaspersky MSSQL Aug 2019)(Citation: Microsoft xp_cmdshell 2017) 

Microsoft SQL Server can enable common language runtime (CLR) integration. With CLR integration enabled, application developers can write stored procedures using any .NET framework language (e.g. VB .NET, C#, etc.).(Citation: Microsoft CLR Integration 2017) Adversaries may craft or modify CLR assemblies that are linked to stored procedures since these CLR assemblies can be made to execute arbitrary commands.(Citation: NetSPI SQL Server CLR)

## Exhaustive test law

This is an ATT&CK sub-technique. Inventory every asset/account/network path where the procedure can run on the listed platforms. Execute (or purple-team simulate) **every** procedure variant in the description — not one benign example. Complete means: each in-scope instance was exercised or ruled out with saved evidence, detections were checked against the same evidence, mitigations were bypass-tested, and mapped CAPEC/CWE procedures were run.

A detection rule without an execution attempt is not a T1505.001 test.

## Procedure

1. **Applicability gate.** If none of the platforms/domains exist in scope, record `T1505.001 N/A: <reason>` and stop.
2. **Instance inventory.** Hosts, identities, SaaS apps, ICS nodes, mobile devices. One workstation is not an inventory.
3. **Oracle.** Define pass/fail: procedure succeeded (control bypassed / action completed) vs blocked vs detected.
4. **Execute / emulate.** Follow the technique description as the minimum procedure set. Persist command output, proxy logs, or pcap under `/tmp` or the engagement dir and **re-read** it.
5. **Sub-techniques.** If this ID has children, open each child file and run it. Parent-only testing is incomplete when sub-techniques exist.
6. **Detection check.** Using the same evidence, ask whether the listed data sources would have fired. Missing telemetry is a finding (visibility gap), not a skip.
7. **Mitigation negation.** For each mitigation below, retry with the control on and bypassed. Unchanged oracle = control failed.
8. **CAPEC / CWE close-out.** Run each mapped CAPEC file in the `capec` skill, then related CWE files in `cwe`. ATT&CK without CWE is a procedure note, not a weakness finding.
9. **Report.** Cite `T1505.001`, tactic, CAPEC/CWE IDs, instance, oracle, evidence path.
