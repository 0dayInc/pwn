# T1009: Binary Padding


**Revoked** in current ATT&CK — still test if the behavior exists; prefer the replacement technique.

- Catalog: [T1009](https://attack.mitre.org/techniques/T1009)
- Kind: technique · ATT&CK 19.2
- Domains: enterprise-attack
- Version: 1.2

## Technique

Adversaries can use binary padding to add junk data and change the on-disk representation of malware without affecting the functionality or behavior of the binary. This will often increase the size of the binary beyond what some security tools are capable of handling due to file size limitations.

Binary padding effectively changes the checksum of the file and can also be used to avoid hash-based blacklists and static anti-virus signatures.(Citation: ESET OceanLotus) The padding used is commonly generated by a function to create junk data and then appended to the end or applied to sections of malware.(Citation: Securelist Malware Tricks April 2017) Increasing the file size may decrease the effectiveness of certain tools and detection capabilities that are not designed or configured to scan large files. This may also reduce the likelihood of being collected for analysis. Public file scanning services, such as VirusTotal, limits the maximum size of an uploaded file to be analyzed.(Citation: VirusTotal FAQ)

## Procedure

1. **Applicability gate.** If none of the platforms/domains exist in scope, record `T1009 N/A: <reason>` and stop.
2. **Instance inventory.** Hosts, identities, SaaS apps, ICS nodes, mobile devices. One workstation is not an inventory.
3. **Oracle.** Define pass/fail: procedure succeeded (control bypassed / action completed) vs blocked vs detected.
4. **Execute / emulate.** Follow the technique description as the minimum procedure set. Persist command output, proxy logs, or pcap under `/tmp` or the engagement dir and **re-read** it.
5. **Sub-techniques.** If this ID has children, open each child file and run it. Parent-only testing is incomplete when sub-techniques exist.
6. **Detection check.** Using the same evidence, ask whether the listed data sources would have fired. Missing telemetry is a finding (visibility gap), not a skip.
7. **Mitigation negation.** For each mitigation below, retry with the control on and bypassed. Unchanged oracle = control failed.
8. **CAPEC / CWE close-out.** Run each mapped CAPEC file in the `capec` skill, then related CWE files in `cwe`. ATT&CK without CWE is a procedure note, not a weakness finding.
9. **Report.** Cite `T1009`, tactic, CAPEC/CWE IDs, instance, oracle, evidence path.
