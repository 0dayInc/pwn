# T1602.002: Network Device Configuration Dump

- Catalog: [T1602.002](https://attack.mitre.org/techniques/T1602/002)
- Kind: sub-technique · ATT&CK 19.2
- Domains: enterprise-attack
- Version: 1.1

## Technique

Adversaries may access network configuration files to collect sensitive data about the device and the network. The network configuration is a file containing parameters that determine the operation of the device. The device typically stores an in-memory copy of the configuration while operating, and a separate configuration on non-volatile storage to load after device reset. Adversaries can inspect the configuration files to reveal information about the target network and its layout, the network device and its software, or identifying legitimate accounts and credentials for later use.

Adversaries can use common management tools and protocols, such as Simple Network Management Protocol (SNMP) and Smart Install (SMI), to access network configuration files.(Citation: US-CERT TA18-106A Network Infrastructure Devices 2018)(Citation: Cisco Blog Legacy Device Attacks) These tools may be used to query specific data from a configuration repository or configure the device to export the configuration for later analysis.

## Procedure

1. **Applicability gate.** If none of the platforms/domains exist in scope, record `T1602.002 N/A: <reason>` and stop.
2. **Instance inventory.** Hosts, identities, SaaS apps, ICS nodes, mobile devices. One workstation is not an inventory.
3. **Oracle.** Define pass/fail: procedure succeeded (control bypassed / action completed) vs blocked vs detected.
4. **Execute / emulate.** Follow the technique description as the minimum procedure set. Persist command output, proxy logs, or pcap under `/tmp` or the engagement dir and **re-read** it.
5. **Sub-techniques.** If this ID has children, open each child file and run it. Parent-only testing is incomplete when sub-techniques exist.
6. **Detection check.** Using the same evidence, ask whether the listed data sources would have fired. Missing telemetry is a finding (visibility gap), not a skip.
7. **Mitigation negation.** For each mitigation below, retry with the control on and bypassed. Unchanged oracle = control failed.
8. **CAPEC / CWE close-out.** Run each mapped CAPEC file in the `capec` skill, then related CWE files in `cwe`. ATT&CK without CWE is a procedure note, not a weakness finding.
9. **Report.** Cite `T1602.002`, tactic, CAPEC/CWE IDs, instance, oracle, evidence path.
